## Exact-length 0x300A JSON transfer

At 11:16:39 UTC, the raw CAN stream carries this block download:

```json
{"DebugUI":{"HiHeapRemaining":"33054720"}}
```

The initiate request is:

```text
C2 0A 30 00 2A 00 00 00
```

so the indicated size is 42 bytes.

That is exactly the JSON byte length. Unlike most previously observed
`0x300A:00` transfers, this message has **no trailing NUL**.

The old bridge receiver subtracted one from every indicated JSON size. It
therefore emitted this transfer after 41 bytes as:

```text
{"DebugUI":{"HiHeapRemaining":"33054720"}
```

The sixth/final block segment arrived ~12 ms later carrying the missing final
brace.

The transport has been corrected so both forms are valid:

1. indicated size equals JSON bytes exactly; or
2. indicated size equals JSON bytes + one observed trailing NUL.

The firmware and offline analyzer now use the same rule, and an exact fixture
from this archive is covered by regression tests.
